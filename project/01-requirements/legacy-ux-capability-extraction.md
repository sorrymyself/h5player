> 最后更新：2026-08-12  
> 关联：REQ-001、REQ-003、REQ-UX-002、ARCH-004、ADR-0009/0015、RISK-021/028/029  
> 证据范围：Legacy 源码静态取证 + Web Extension Phase 6 当前实现；不表示 Legacy 所有历史行为都已被取证

## 1. 目的与边界

本文件把 Legacy 油猴脚本中对用户有价值的可观察体验提炼为产品能力，供 Web Extension 重新设计和测试使用。

以下内容属于吸收对象：

- 控件和当前媒体的空间归属；
- 页面操作的低干扰即时反馈；
- 用户明确设置的倍速在新媒体、重播和站点切换中的继承；
- 快捷键、页面聚焦和 UI 入口之间的低认知负担协作；
- 多媒体、音频、动态页面和站点干预下的可预测降级。

以下内容不属于直接迁移对象：

- Legacy 的全局对象、DOM 直接调用、属性劫持、CSP/Shadow DOM 改写、远程 helper 或任意脚本配置；
- Legacy 的 Shoelace/Lit/Vue 具体组件结构、CSS 类名和实现时序；
- Legacy 为兼容历史站点留下的未审查 hack；
- “代码相似”或“内部字段相似”本身作为完成证据。

## 2. 证据与结论

### 2.1 页面控件跟随媒体，而不是跟随视口

**Evidence**

- `src/h5player/h5player.js:193-210` 计算当前播放器的包裹容器。
- `src/h5player/h5player.js:373-413` 在播放器初始化、播放、暂停、时间变化和尺寸变化时注册或重新定位 UI。
- `src/h5player/ui/h5playerUI.js:111-180` 为每个 video 建立 popup，并把 Popper anchor 指向该 video。
- `src/h5player/ui/h5playerUI.js:364-467` 依据 visibility、play/pause、timeupdate 和尺寸变化调整显隐与位置。

**产品结论**

页面控件的空间归属必须是某个具体媒体实例；视口级 UI 只能作为 Popup/Options 或明确打开的辅助面板，不能作为默认页面控制面板。

### 2.2 控件默认低干扰，操作时才提高可见性

**Evidence**

- `src/h5player/ui/h5playerUI.js:229-274` 鼠标进入控件时提升可见性，离开后延迟收起。
- `src/h5player/ui/h5playerUI.js:364-396` 播放中默认隐藏或降低可见性，暂停且已播放一段时间时恢复入口。
- `src/h5player/ui/shoelace/themes/light.css:478-565` 默认透明度为 0，激活态为半透明，悬停时才完全显示。
- `src/h5player/h5player.js:127-135` 提供关闭当前实例 UI 和临时关闭页面 UI 的能力。

**产品结论**

默认页面体验应优先保证视频内容和站点原生控件；页面 UI 必须可关闭、可按站点停用、可临时停用，并在播放期间不持续遮挡内容。

### 2.3 反馈锚定当前媒体，短暂、覆盖式且不抢交互

**Evidence**

- `src/h5player/h5player.js:1576-1704` 根据当前播放器找到容器、写入消息、显示并在约 2 秒后隐藏。
- `src/h5player/h5player.js:1707-1758` 视频提示使用媒体包裹容器内的绝对定位；音频退化为右下角固定提示。
- `src/h5player/h5player.js:672-736`、`:1089-1191`、`:1490-1525` 等操作在成功后反馈最终倍速、音量、播放/暂停状态。
- `src/h5player/h5player.js:1651-1703` 新消息会清理旧定时器，避免多个提示堆叠。

**产品结论**

即时反馈必须和命令结果绑定，默认位于当前媒体右上角或等效不遮挡安全区；反馈不能使用全局大面板，也不能只显示“已发送命令”而不显示最终值。

### 2.4 倍速是用户意图，不只是当前媒体瞬态

**Evidence**

- `src/h5player/configManager.js:4-21` 保存 `media.playbackRate` 与 `media.lastPlaybackRate`。
- `src/h5player/h5player.js:263-300` 在 `playing` 生命周期重新应用倍速；首次播放还会再次同步设置。
- `src/h5player/h5player.js:607-627` 从配置读取并归一化倍速。
- `src/h5player/h5player.js:711-736` 用户设置后保存倍速并同步当前页面的其他媒体。
- `src/h5player/h5player.js:846-864` `resetPlaybackRate` 在 1x 与上次倍速之间切换，并保存上次非 1x 值。
- `src/h5player/configManager.js:338-345` 默认开启阻止网站重置倍速的策略。

**产品结论**

Web Extension 必须把“用户明确设置的倍速”与“媒体当前实际倍速”分开建模：前者可成为全局或站点策略，后者属于单媒体运行状态。新媒体、重新加载、SPA 换集和网站反向改值时，应按策略自动收敛，而不是要求用户重复点击。

### 2.5 快捷键与 UI 是同一套命令语义的不同入口

**Evidence**

- `src/h5player/configManager.js:158-224` 定义播放、快进、音量、倍速和固定值快捷键。
- `src/h5player/h5player.js:2223-2304` 先排除可编辑元素，再处理启用状态、全局/聚焦模式和命令分发。
- `src/h5player/ui/js/menu.js:749-797` UI 菜单最终调用播放器命令，并为 UI 设置倍速绕过短时锁。

**产品结论**

快捷键、页面控件、Popup 和 Options 必须复用同一类型化命令和策略服务；用户可以先用页面控件低成本上手，再逐步使用快捷键提效，且两者反馈一致。

### 2.6 多媒体控制应保持当前媒体归属，不等于所有状态无差别广播

**Evidence**

- `src/h5player/h5player.js:137-190` 维护媒体列表和当前播放器。
- `src/h5player/h5player.js:726-733` 对倍速进行页面内媒体同步。
- Web Extension `web-extension/src/domain/adapter/active-player-scoring.ts:50-125` 已按可见性、焦点、最近交互、播放状态和面积选择 active media。
- Web Extension `web-extension/src/infrastructure/dom/media-discovery-service.ts:470-506` 已保持 active media 与其他 media snapshot 分离。

**产品结论**

倍速这类用户意图可以按明确策略同步到页面内新媒体；音量、静音、播放/暂停、画面变换等必须有独立的作用域定义，不能因为“全局统一”而误控广告、背景音频或第二个视频。

### 2.8 交互细节的通用化规则

- 高频操作必须同时提供“低认知页面入口”和“高效率快捷键入口”，但两者共享命令、作用域和反馈。
- 固定值、增量操作和 reset 都应反馈执行后的最终值；网站/浏览器 clamp 后不能显示请求值冒充实际值。
- 用户停用的 UI/快捷键/站点状态必须稳定，不因 `play`、`timeupdate`、路由变化或新媒体发现而自动反转。
- 能力型控件只在 capability 为真时展示或启用；失败时保留当前媒体核心控制，不让单个高级能力拖垮页面 runtime。
- 持久化只用于明确的用户偏好或策略；播放/暂停、当前时间、临时 visual state 等实例状态不得无意升级为全局配置。
- 所有自动行为必须可关闭、可诊断、有界且可恢复；“为了兼容”不能成为无限轮询、页面污染或静默扩大作用域的理由。

## 3. 吸收原则

1. **先归属，再反馈**：任何页面 UI 或反馈都必须先绑定稳定的 `mediaId` 和媒体锚点。
2. **用户意图优先于网站瞬态**：明确设置的策略优先于网站后续重置，但尊重能力声明、站点规则和用户停用。
3. **默认低干扰，主动操作可见**：不以持续面板占据视口；主动点击或快捷键后才展示短暂反馈。
4. **同一语义，多种入口**：快捷键、页面控件、Popup 和 Options 共享 command/application 语义，不共享布局。
5. **实例状态与策略分离**：单媒体视觉状态、播放状态、当前时间等不自动升级为全局设置；用户意图必须显式持久化。
6. **失败可解释且不打断**：命令失败反馈原因和可行动建议；反馈本身不能造成页面崩溃或阻塞播放。
7. **吸收行为，不复刻缺陷**：旧脚本中造成页面样式修改、全局污染、任意执行或安全边界扩大的做法不进入 Web Extension。

## 4. 待产品确认的行为选择

以下事项不能仅从 Legacy 实现推导为最终产品决策，应在本文件评审时确认：

| 决策项         | 推荐默认                                       | 需要确认的影响                                 |
| -------------- | ---------------------------------------------- | ---------------------------------------------- |
| 倍速作用域     | 全局默认 + 站点覆盖 + 当前页面会话显式临时覆盖 | 是否允许用户只改当前媒体而不改站点策略         |
| 页面内倍速同步 | 默认同步新媒体；当前媒体临时覆盖不自动写入策略 | 广告/背景音频是否排除，站点 adapter 是否可阻止 |
| 页面控件显隐   | 播放中隐藏或低透明度；悬停/焦点/暂停时展开     | 触控设备没有 hover 时的打开手势                |
| 反馈位置       | 视频右上角安全区；音频右下角                   | 站点原生控件、字幕和 PiP 的避让策略            |
| 反馈时长       | 约 1.5～2.0 秒；连续操作合并                   | 是否允许用户调整时长或关闭动画                 |
| 失败反馈       | 就地短提示，必要时 Popup/Options 展示详情      | 页面不可用时是否退化为 Popup 状态              |
| 多媒体全局控制 | 仅对策略明确的字段广播                         | 用户是否需要“仅当前媒体/当前页面全部媒体”切换  |

## 5. 明确不吸收的 Legacy 行为

- 通过 `Object.defineProperty` 或事件代理阻止网站逻辑的具体实现方式；只吸收“保护用户策略”的产品目标。
- 通过修改宿主容器 inline style、解除 closed Shadow DOM 或改写 CSP 来保证显示；只吸收“UI 能可靠显示且可撤销”的目标。
- 使用全局 `window` 对象、Tampermonkey `GM_*` 或页面 localStorage 作为 Web Extension 权威状态。
- 远程推荐/helper、自定义任意函数和实验性下载能力的默认暴露。

## 6. 证据边界

Legacy 静态代码证明了实现意图和若干当前行为；它没有证明所有真实站点上的布局、焦点、字幕避让、触控行为和播放策略均一致。上述行为在 Web Extension 中必须通过 fixture、组件测试、真实扩展 E2E 和真实站点人工 smoke 分层验证。
