# H5Player Web Extension 产品与重构需求

> 文档 ID：REQ-001  
> 状态：Approved Planning Baseline / Phase 6.5 UX Amendment In Review
> 负责人：Product Owner  
> 最后更新：2026-08-16
> 关联：GOV-001、ADR-0001、ADR-0015/0016、REQ-UX-001、REQ-UX-002、REVIEW-UX-001

> 说明：Phase 0～6 的既有基线结论继续有效；本文件中标记为 Phase 6.5 的新增或升格需求处于 `In Review`，在用户审核前不得视为已批准实现范围。

## 1. 问题陈述

当前 Web Extension 能运行的前提是把 Legacy 油猴代码直接打进 `inject.js`，再模拟 GM API。该实现没有独立的类型模型、消息协议、权限治理、自动化测试和发布体系，且包含通过修改页面 CSP、内联代码和 `new Function` 兜底注入的高风险路径，无法作为长期产品架构。

需要在不翻修油猴主线的前提下，重新构建一个独立、可靠、可扩展的 Web Extension，并用它验证未来可共享的工程模式。

## 2. 目标用户与场景

### 2.1 目标用户

- 需要在多个网站统一使用快捷键控制 HTML5 视频的用户。
- 需要倍速、跳转、音量、画面、全屏、画中画、截图和进度恢复等增强能力的用户。
- 需要针对单个网站关闭、调整或诊断扩展行为的高级用户。
- 维护站点兼容配置、审查权限和发布扩展的开发维护者。

### 2.2 核心场景

- 普通页面只有一个 `<video>`，用户无需配置即可使用常用快捷键。
- 页面动态创建/销毁多个媒体元素，扩展能选中当前有效播放器。
- 视频位于同源/跨源 iframe 或开放/封闭 Shadow DOM 周边结构中。
- SPA 路由切换后不重复初始化、不丢失状态、不泄漏监听器。
- 网站主动重置 `playbackRate`、`volume` 或拦截事件时，扩展按用户配置选择是否干预。
- 用户从 popup、页面悬浮 UI、快捷键或 options 修改同一配置，状态保持一致。
- 出现兼容问题时，用户能一键停用当前站点并导出脱敏诊断信息。

## 3. 产品原则

- 默认行为可预测，实验能力明确隔离。
- 用户操作优先于网站自动控制，但不以破坏网页安全策略为代价。
- 全局配置与站点覆盖规则清晰，不发生多 Tab 互相覆盖。
- 页面控制与即时反馈必须归属于具体媒体，不以持续视口级大面板遮挡内容。
- 用户明确设置的倍速属于可继承意图，不因新媒体、重播、换集或 `src` 变化而静默丢失。
- 扩展不能静默扩大权限、上传浏览记录或执行远程代码。
- 站点兼容失败应局部降级，不能拖垮所有页面。

## 4. 功能范围与优先级

优先级定义：P0 为稳定版必需；P1 为稳定版目标；P2 为后续增强或实验能力。

### 4.1 启动、发现与生命周期

- **FR-BOOT-001 P0**：在获得站点权限后，于 `document_start` 建立一次且仅一次的扩展会话。
- **FR-BOOT-002 P0**：发现动态插入、移除及复用的 HTMLMediaElement，并维护无泄漏的实例生命周期。
- **FR-BOOT-003 P0**：支持普通 DOM、开放 Shadow DOM、SPA 路由和多播放器页面。
- **FR-BOOT-004 P1**：支持同源 iframe；跨源 iframe 仅在浏览器已授权其 origin 时独立运行并与父页面协调。Web Extension 以 host permission、真实 sender frame 和精确 owner 路由替代 Legacy `allowCrossOriginControl`，扩展设置不得扩大浏览器权限（ADR-0019）。
- **FR-BOOT-005 P1**：提供当前站点/页面临时停用、永久停用和恢复入口。

### 4.2 播放器选择与会话

- **FR-SESSION-001 P0**：依据可见性、尺寸、播放状态、最近交互和焦点选择 active player。
- **FR-SESSION-002 P0**：切换 active player 时保留正确配置，但不得把实例临时状态错误传播给其他播放器。
- **FR-SESSION-003 P1**：页面存在音频、广告小窗或背景媒体时，避免误控制。
- **FR-SESSION-004 P0（Phase 6.5 In Review）**：页面控件、即时反馈和默认命令目标必须共享同一稳定 `mediaId`；active player 变化时三者同步迁移，旧媒体资源立即清理。

### 4.3 核心播放控制

- **FR-CORE-001 P0**：播放/暂停、前进/后退、设置与增减播放速度。
- **FR-CORE-002 P0**：设置与增减音量、静音；范围和步长经过统一校验。
- **FR-CORE-003 P0**：用户可配置是否阻止网站重置播放速度、音量和进度。
- **FR-CORE-004 P0**：所有操作通过类型化 Command Registry 执行，快捷键与 UI 不直接调用播放器实现。
- **FR-CORE-005 P1**：逐帧、下一集/上一集等能力按媒体和站点能力动态显示。
- **FR-CORE-006 P0（Phase 6.5 In Review）**：播放倍速必须区分全局默认、站点策略、页面临时覆盖、当前媒体临时值和媒体实际值；UI 必须显示有效值及来源，写回作用域可预测。
- **FR-CORE-007 P0（Phase 6.5 In Review）**：新媒体、重播、SPA 换集、`src` 变化及网站反向改值时，运行时按有效策略幂等应用用户倍速意图；保护重试必须有界且可诊断，不得无限轮询。
- **FR-CORE-008 P0（Phase 6.5 In Progress）**：MAIN world 必须建立按媒体实例隔离的控制权仲裁层。扩展内部写入使用启动时捕获的原生 accessor；网站后续对 `playbackRate`、`volume`、`muted` 和受保护 seek 窗口内 `currentTime` 的冲突写入，按 resolved policy 拒绝、允许或降级，不能静默覆盖已确认的用户意图。
- **FR-CORE-009 P0（Phase 6.5 In Progress）**：控制权保护必须可配置、可撤销、可诊断并具有站点例外。倍速和音量使用持续意图保护；进度只使用用户 seek/恢复后的短时租约且默认关闭；媒体移除、换源 generation、页面停用、权限撤销、frame 销毁和扩展 teardown 必须释放保护，不得永久修改宿主原型或依赖无限轮询。

### 4.4 快捷键

- **FR-HOTKEY-001 P0**：保留 Legacy 核心快捷键语义，并允许用户修改、禁用和恢复默认值。
- **FR-HOTKEY-002 P0**：输入框、可编辑元素、组合键冲突、按键长按和重复触发有确定规则。
- **FR-HOTKEY-003 P0**：检测冲突和非法组合，保存前给出可理解错误。
- **FR-HOTKEY-004 P1**：支持全局页面模式与播放器聚焦模式切换。

### 4.5 画面与显示

- **FR-VISUAL-001 P1**：缩放、平移、旋转、水平/垂直镜像和画面滤镜。
- **FR-VISUAL-002 P1**：重置操作原子恢复默认画面状态。
- **FR-VISUAL-003 P1**：网页全屏、原生全屏与 Picture-in-Picture，优先调用站点适配能力，失败时使用通用实现。
- **FR-VISUAL-004 P1**：页面内 UI 使用 Shadow DOM 或等效隔离，不污染页面样式和全局命名。

### 4.6 截图、进度和跨 Tab

- **FR-MEDIA-001 P1**：对允许绘制到 Canvas 的视频截图，输出明确文件名和失败原因。
- **FR-MEDIA-002 P1**：按用户开关保存和恢复播放进度，并有容量、过期和隐私策略。
- **FR-MEDIA-003 P1**：跨 Tab 只同步经过定义的全局状态；不得依赖高频轮询或伪造 GM 变更事件。
- **FR-MEDIA-004 P2**：媒体流下载、MediaSource 捕获和音频增益作为独立实验模块，默认关闭。

### 4.7 站点适配

- **FR-ADAPTER-001 P0**：提供通用适配器，未配置站点仍可使用核心能力。
- **FR-ADAPTER-002 P1**：站点适配器具有匹配条件、优先级、能力声明、生命周期 Hook 和独立测试。
- **FR-ADAPTER-003 P1**：选择器式适配优先，命令式 Hook 作为受限逃生口；单个适配器异常不得影响核心。
- **FR-ADAPTER-004 P1**：适配器支持按版本/功能标记禁用，并在诊断报告中显示命中情况。
- Phase 5 细化：首批 Tier 1 为 YouTube、Bilibili、Tencent Video、iQIYI、Youku；Tier 2 为 Netflix、Ixigua、AcFun、
  Sohu Video、TED。其自动化证据以固定脱敏 fixture 为主，真实站点 smoke 必须单独记录，不能由 fixture 结果推断。
- Phase 5 细化：adapter registry 只接受静态 hostname/path、priority、能力和受限 selector/Hook；所有站点异常必须保持
  GenericAdapter 可用，且诊断只输出 bounded metadata。
- **FR-ADAPTER-005 P2**：外部自定义配置改为显式导入的受限 Schema；首个稳定版不执行任意用户函数。

### 4.8 设置与数据

- **FR-CONFIG-001 P0**：定义版本化、可校验的全局配置、站点覆盖和会话状态模型。
- **FR-CONFIG-002 P0**：配置读取优先级固定为：会话覆盖 > 站点覆盖 > 全局配置 > 默认值。
- **FR-CONFIG-003 P0**：所有写入通过仓储接口，支持跨上下文订阅、并发更新和迁移。
- **FR-CONFIG-004 P0**：支持导出、导入、恢复默认与迁移前备份；导入失败不破坏现有数据。
- **FR-CONFIG-005 P1**：仅将适合且不敏感的小型配置同步到 `storage.sync`；本地存储为权威数据源。
- **FR-CONFIG-006 P2**：支持从 Legacy 导出 JSON 的一次性转换；不尝试直接读取 Tampermonkey 私有存储。

### 4.9 扩展 UI

- **FR-UI-001 P0**：popup 显示当前页面连接状态、active player、常用操作和站点开关。
- **FR-UI-002 P0**：options 提供配置、快捷键、站点列表、数据导入导出和诊断入口。
- **FR-UI-003 P0（Phase 6.5 升格，In Review）**：页面悬浮 UI 必须按媒体实例挂载并跟随媒体位置，只呈现当前媒体高频操作；默认不得显示视口级大控制面板，并可按实例、页面或站点禁用。
- **FR-UI-004 P1**：UI 状态来自类型化应用服务，组件不直接调用浏览器 API 或媒体对象。
- **FR-UI-005 P1**：中文和英文为首发完整语言；其他 Legacy 语言按资源成熟度逐步迁移。
- **FR-UI-006 P0（Phase 6.5 In Review）**：快捷键、页面控件和 Popup 的成功/失败结果必须生成统一的媒体级即时反馈；默认锚定当前媒体安全区、短暂显示最终值、不抢焦点且不拦截媒体交互。
- **FR-UI-007 P0（Phase 6.5 In Review）**：页面控件默认折叠或低可见，只允许从倍速状态区通过 hover、键盘焦点或触控/点击明确打开；媒体暂停必须强制收起面板并仅显示短暂状态反馈，播放过程中不持续遮挡媒体主体，空间不足时收缩为单一入口。
- **FR-UI-008 P1（Phase 6.5 In Review）**：新用户无需记忆快捷键即可通过少量直观控件完成播放、跳转、倍速、音量和静音；高级能力进入二级菜单、Popup 或 Options。

### 4.10 诊断与支持

- **FR-DIAG-001 P0**：提供结构化本地日志级别，默认只记录必要错误且不远程上传。
- **FR-DIAG-002 P0**：诊断导出包含版本、浏览器、权限、模块、适配器和错误摘要，并默认移除 URL 查询、标题和用户内容。
- **FR-DIAG-003 P1**：UI 可显示扩展未运行的原因：无权限、站点禁用、无媒体、上下文初始化失败或功能不支持。

## 5. 非目标与延期能力

首个稳定版明确不以以下内容作为阻塞项：

- 完整复制 Legacy 的推荐信息、捐赠入口和远程助手行为；
- 远程代码、任意脚本注入或从网络加载 UI 资源；
- 通过改写 CSP 绕过网站安全策略；
- 对所有历史站点适配器一次性 100% 迁移；
- DRM 内容下载、绕过付费/访问控制或违反平台规则的能力；
- Safari、iOS、Android 和国产浏览器的正式支持承诺。

## 6. 浏览器与分发基线

- Chromium：Chrome 与 Edge 最新两个稳定大版本。
- Firefox：最新稳定版与当前 ESR。
- Manifest：MV3；浏览器差异由适配层和构建配置管理。
- 渠道：Development、Alpha、Beta、Stable。
- Stable 前不得使用无法解释的全站网络拦截权限。

## 7. 关键产品决策

以下采用推荐默认值，但在公开 Beta 前必须形成最终 ADR：

| 决策          | 推荐值                                                          | 原因                             |
| ------------- | --------------------------------------------------------------- | -------------------------------- |
| 站点权限      | 首次引导选择“所有站点”或“按站点启用”，默认不静默授权            | 平衡开箱即用与商店权限提示       |
| 远程遥测      | 默认无遥测                                                      | 降低隐私与审核风险               |
| 下载功能      | 独立实验模块、默认关闭                                          | 技术与合规风险高                 |
| 自定义配置    | 受限声明式 Schema                                               | 禁止任意代码执行                 |
| 配置同步      | 本地为主、白名单字段同步                                        | 避免配额与隐私问题               |
| 跨 frame 控制 | host permission 授权 + 精确 frame owner；不复制 Legacy 广播开关 | 避免双重授权事实源和页面伪造目标 |

## 8. 验收总则

- 每个 P0/P1 需求必须在功能矩阵中映射到模块、任务和测试。
- “与 Legacy 一致”只指文档明确的可观测行为，不包含旧实现细节或安全缺陷。
- 任何需求若只能手工验证，必须说明自动化缺口、负责人和补齐期限。
- Stable 版本不得存在未接受风险的 P0/P1 缺陷。
- Phase 6.5 的 `FR-SESSION-004`、`FR-CORE-006..009`、`FR-UI-003/006/007/008` 必须按
  [媒体 UI、反馈与倍速体验质量验收矩阵](../05-quality/ux-acceptance-and-test-matrix.md) 提供自动化、headed 视觉和真实站点分层证据；完成前 Phase 7 保持冻结。
