# Web Extension 媒体 UI 与交互细化需求

## 1. 交付目标

当前 Web Extension 的基础媒体控制可用，但页面 UI 尚未达到 Legacy 的低干扰、高反馈、低重复操作标准。本需求将页面 Overlay 从“视口级控制面板”调整为“媒体实例级轻量控制层”，并补齐倍速策略闭环。

完成本需求前不得进入 Phase 7 实验能力或 Legacy 共享核心决策。

## 2. 用户故事

| ID        | 用户故事                                                                             | 价值                             |
| --------- | ------------------------------------------------------------------------------------ | -------------------------------- |
| US-UX-001 | 作为刷视频的用户，我希望页面控件紧贴当前视频，而不是占据整个视口                     | 不打断内容消费                   |
| US-UX-002 | 作为快捷键用户，我希望按键后在当前视频右上角立即看到最终值                           | 确认操作生效且无需打开面板       |
| US-UX-003 | 作为连续观看用户，我希望设置一次倍速后，新视频/换集/重播自动沿用                     | 消除重复操作                     |
| US-UX-004 | 作为新用户，我希望先通过少量直观控件完成播放、快进和倍速设置，再学习快捷键           | 降低上手认知负担                 |
| US-UX-005 | 作为多媒体页面用户，我希望控制目标可预测，不误控广告或背景音频                       | 避免错误操作                     |
| US-UX-006 | 作为遇到兼容问题的用户，我希望能临时隐藏页面 UI，同时保留快捷键或 Popup 控制         | 保持可恢复性                     |
| US-UX-007 | 作为已明确设置倍速、音量或进度的用户，我希望网站后台轮询或换集逻辑不能静默夺回控制权 | 保持操作结果稳定和用户自主决定权 |

## 3. 页面 UI 形态

### 3.1 默认形态

- 每个可支持的 video 只能拥有一个与其绑定的 UI 实例；同一媒体重复发现不得重复挂载。
- UI 的 anchor 必须是该媒体或经验证的局部媒体容器，不得默认挂在 `document.documentElement` 后再以视口固定坐标模拟跟随。
- UI 默认处于折叠/低可见状态；播放中不得显示大面积面板。
- UI 展开后只显示高频操作：播放/暂停、后退/前进、倍速、音量/静音；画面、全屏、截图等放入二级菜单或 Popup/Options。
- 展开宽度、高度和覆盖面积必须有稳定上限；不得覆盖媒体主要内容区域超过约 20%。具体像素阈值需在 UI spike 中用真实站点校准。
- UI 具备显式“隐藏当前实例”“临时隐藏本页”“关闭页面 UI”入口，状态与 Popup/Options 一致。

### 3.2 显隐状态

```text
unmounted
  -> mounted-collapsed
  -> expanded-by-trigger-interaction
  -> collapsed-after-idle
  -> hidden-by-user
  -> unmounted-on-media-remove
```

- `mounted-collapsed`：不拦截媒体交互，容器 `pointer-events` 仅在实际控件区域启用。
- `expanded-by-trigger-interaction`：仅倍速状态区的鼠标悬停、键盘焦点或触控/点击明确手势可以触发展开；媒体暂停、反馈到达和状态刷新不得自动展开。
- 媒体从播放切换到暂停时必须立即收起已展开面板并清理悬浮/焦点展开状态，只复用倍速状态区短暂显示“已暂停”等反馈。
- `collapsed-after-idle`：最后一次操作或离开控件后延迟收起；展开菜单关闭，避免残留遮挡。
- `hidden-by-user`：当前媒体或页面临时隐藏；除非用户恢复，不因 `play`/`timeupdate` 自动重建可见 UI。
- 媒体移除、frame 销毁、权限撤销或站点停用必须 teardown host、listener、observer、timer。

### 3.3 媒体定位与避让

- 每次定位使用媒体 `DOMRect` 和局部容器边界，不依赖首次挂载坐标。
- 在滚动、resize、fullscreen、PiP、SPA 路由和媒体尺寸变化后重新定位。
- 默认优先媒体右上角；若空间不足按 `top-right -> top-left -> bottom-right -> bottom-left` 选择安全位置。
- 控件不得覆盖原生播放按钮、字幕区域、站点关键按钮或媒体外的页面正文；无法确认安全区时收缩为单一入口按钮。
- 绝不通过修改宿主页面原有 inline style、CSP 或 Shadow DOM 模式来换取定位成功。
- iframe-only media 在 frame registry 尚未完成前，不得伪装成 top-frame 已就绪；应显示明确空状态或仅提供 Popup 入口。

## 4. 即时反馈需求

### 4.1 反馈模型

反馈事件属于 `mediaId` 作用域，至少包含：

```ts
interface MediaFeedbackEvent {
  readonly id: string;
  readonly mediaId: string;
  readonly commandId: string;
  readonly kind: "value" | "state" | "error" | "policy";
  readonly messageKey: string;
  readonly value?: number | string | boolean;
  readonly tone: "neutral" | "success" | "warning" | "danger";
  readonly createdAt: number;
  readonly expiresAt: number;
}
```

- UI 不直接从 DOM 猜测反馈；命令执行结果和最新媒体 snapshot 是反馈事实源。
- 同一媒体在反馈尚未消失时再次操作，应合并/替换为最新值，不堆叠多个 toast。
- 反馈默认 `1.5～2.0s` 可见，`prefers-reduced-motion` 下仍必须立即可读。
- 反馈使用 `aria-live="polite"`；错误使用 `role="alert"`，但不得抢走用户焦点。
- 反馈 `pointer-events: none`，除非它包含用户明确触发的恢复操作。
- 反馈文本应显示最终值，例如 `播放速度 1.5x`、`音量 80%`、`后退 5 秒`、`已暂停`，而不是只显示“操作成功”。

### 4.2 操作反馈矩阵

| 操作             | 成功反馈                                | 作用域                 | 是否更新持久化意图                            |
| ---------------- | --------------------------------------- | ---------------------- | --------------------------------------------- |
| 播放/暂停        | `已播放` / `已暂停`                     | 当前媒体               | 否                                            |
| 前进/后退        | `前进 5 秒` / `后退 30 秒`              | 当前媒体               | 否                                            |
| 设置倍速         | `播放速度 1.5x`                         | 当前媒体 + 按策略同步  | 是，默认写入当前站点策略/全局默认需由产品确认 |
| 增减倍速         | `播放速度 1.4x`                         | 当前媒体 + 按策略同步  | 是                                            |
| 1/2/3/4 倍速     | `播放速度 2x`                           | 当前媒体 + 按策略同步  | 是                                            |
| 恢复 1x/上次倍速 | `播放速度 1x` 或上次值                  | 当前媒体 + 按策略同步  | 是                                            |
| 音量增减         | `音量 75%`                              | 当前媒体；可选页面策略 | 默认否                                        |
| 静音             | `已静音` / `已取消静音`                 | 当前媒体               | 默认否                                        |
| 画面变换         | 显示最终 zoom/角度/滤镜值               | 当前媒体               | 否，除非另有明确设置                          |
| 网站反向修改倍速 | `已恢复到 1.5x` 或 `网站策略未允许保护` | 当前媒体               | 不新增意图                                    |
| 命令失败         | 短原因 + 可行动建议                     | 当前媒体               | 否                                            |

### 4.3 反馈位置优先级

1. video：媒体右上角安全区；
2. video 空间不足：媒体内右上角紧凑单行提示；
3. audio：页面右下角紧凑提示，并在 Popup 保留状态；
4. iframe-only：frame 内提示或 Popup 状态，不在错误的 top frame 伪造位置。

## 5. 倍速策略与全局统一控制

### 5.1 作用域模型

倍速至少区分五个概念，其中前四项属于用户意图作用域，最后一项属于媒体运行状态：

| 层                             | 含义                                                 | 生命周期     | 权威                      |
| ------------------------------ | ---------------------------------------------------- | ------------ | ------------------------- |
| Global default                 | 未配置站点覆盖时的默认用户意图                       | 跨页面/重启  | Settings Repository       |
| Site policy                    | 某站点默认倍速及保护策略                             | 站点范围     | Settings Repository       |
| Page session override          | 当前页面临时选择，是否写回策略由用户动作决定         | 当前页面     | Content runtime 内存      |
| Current-media temporary intent | 仅当前媒体的临时选择，不影响本页其他媒体或后续新媒体 | 当前媒体实例 | Content/page-main session |
| Media actual rate              | 某个媒体当前实际值                                   | 媒体实例     | Page-main controller      |

单媒体解析优先级：`current-media temporary intent > page session override > site policy > global default > 1x`。
`Media actual rate` 是执行/观察结果，不参与意图优先级，也不能自动写回设置。网站瞬时值不能覆盖已确认的用户策略，除非站点 adapter 声明该能力不受支持或用户关闭保护。

### 5.2 新媒体与重播

- 新媒体发现后，在其可设置倍速且已达到可操作状态时应用 effective rate。
- `loadedmetadata`、`canplay`、`playing`、SPA 换集、`src` 变化或网站重置倍速后，策略协调器应幂等重放 effective rate。
- 同一媒体同一目标值的重复应用必须去重；站点确实反向覆盖时允许有界重试/短时保护，但不得无限轮询。
- 当前用户明确点击页面控件或使用快捷键设置倍速时，应更新“用户意图”而非只改 DOM 属性。
- 若用户仅想临时控制当前媒体，必须提供“仅当前媒体”路径或临时会话开关，不能强制污染站点策略。
- 倍速值范围统一 `[0.1, 16]`，显示精度和四舍五入规则统一；站点能力更窄时显示降级原因。
- 页面内是否同步全部媒体由策略控制。默认只同步同一页面中可识别为内容媒体的实例，不同步隐藏/背景/广告音频，除非用户明确选择。

### 5.3 网站保护策略

- `protectPlaybackRate` 表示保护用户意图的产品策略；实现采用可撤销的 MAIN world accessor 仲裁为主、有界状态恢复为辅，不把无限轮询作为保护机制。
- 保护失败不得导致页面崩溃；应反馈“当前网站不允许锁定速度”并保留 Popup/Options 诊断。
- 站点 adapter 可以声明 `playbackRate` 不可控、只能在特定生命周期应用，或要求禁用保护；该声明必须有 fixture/真实 smoke 证据。
- 保护开关、站点覆盖和当前页面临时停用应在 Popup/Options 与页面反馈中保持一致。

### 5.4 控制权优先级与属性语义

控制权优先级按“明确用户意图”而不是按脚本执行先后决定：

```text
扩展用户命令 / 已确认持久策略
  > 扩展生命周期重放
    > 经 adapter 声明并验证的站点原生控制路径
      > 网站默认值、轮询修正和播放器初始化重置
```

- 扩展必须在 MAIN world 启动时捕获原生 getter/setter。扩展内部写入直接调用已捕获 setter；网站普通属性赋值经过仲裁 setter。
- `playbackRate`：保护开启且存在 intended value 时采用持续保护。网站写入相同值可通过，冲突值被拒绝或立即恢复；换源、重播和新实例继续继承 resolved policy。
- `volume` 与 `muted`：`protectVolume` 开启且用户或有效默认值已建立后持续保护；站点静音广告、自动恢复音量或轮询回写不得覆盖用户值。
- `currentTime`：不能像倍速一样永久锁定，否则会阻止自然播放。`protectCurrentTime` 只在扩展 seek、进度恢复或明确跳转后建立短时租约，按时间推进容差判断冲突写入；默认关闭。
- 页面原生控制与保护策略冲突时，以用户已选择的保护开关为准；用户可按站点关闭对应保护。adapter 若必须使用站点 API，应声明该属性由 adapter 承担写入与确认，但不能绕过结果验证。
- getter 必须返回媒体真实值或经验证的站点代理值，不能伪造“看起来成功”的 snapshot。

### 5.5 防御层次、恢复与降级

1. **预防层**：按实例拦截冲突 setter，避免网站轮询真正改变媒体值。
2. **确认层**：扩展命令只有在读取到最终实际值与 intended value 一致后才算成功。
3. **恢复层**：若网站缓存了旧 setter、替换了实例或使用自定义媒体元素绕过预防层，生命周期协调器在媒体事件和状态观察时有界重放。
4. **适配层**：站点 adapter 可提供经过验证的原生 API、自定义元素 accessor 或能力降级；不得通过伪造成功掩盖实际未生效。
5. **隔离层**：单个属性或站点失败只降低该能力，不能使快捷键、页面 UI、其他媒体或整个扩展失效。

保护状态至少记录属性、媒体实例、intended/actual、阻止次数、最近冲突值、策略来源、generation 和降级原因。诊断不得记录完整 URL、媒体标题或用户观看内容。

## 6. 快捷键与低认知上手

- 首次安装默认保留 `Space`、方向键、`Ctrl+方向键`、`X/C/Z`、`1/2/3/4` 的核心语义；具体 chord 以 `domain/hotkey/catalog.ts` 为准。
- 页面控件中的倍速入口应提供常用固定值和当前值，避免新用户必须先记忆快捷键。
- 快捷键执行成功后复用同一 `MediaFeedbackEvent`；不能出现“快捷键无反馈、UI 有反馈”的双轨体验。
- 可编辑元素、组合输入、浏览器保留快捷键和站点原生快捷键冲突必须按现有 hotkey policy 阻断或提示。
- 页面 scope/player scope 的差异必须在 UI 中用可理解文案说明；不允许用户只能通过猜测发现当前焦点模式。
- Popup 必须展示当前 active media、当前倍速、保护状态和“打开页面控件/完整设置”的入口；无媒体/无权限/站点停用分别提示。

## 7. 多媒体、音频和动态页面

- active media 变更时，页面轻量控件和反馈目标必须同时切换；旧媒体反馈不能飘到新媒体。
- 多媒体页面中，倍速策略应用和当前媒体控制必须有可追踪的 `mediaId`，不能通过数组 index 猜目标。
- 音频没有可靠媒体矩形时使用页面级紧凑提示，不显示覆盖全屏的面板。
- 动态新增媒体自动纳入策略协调；删除媒体立即 teardown 其 UI、feedback、timer 和 observer。
- Shadow DOM、SPA、同源/跨源 iframe 需分别定义发现、控制、反馈和 UI 归属；未支持的场景显示降级而不是静默失败。

## 8. 可访问性、主题与宿主兼容

- 页面控件与反馈必须在闭合 Shadow Root 或等效隔离中渲染；不使用宿主站点全局 CSS 类名。
- 反馈不依赖颜色或动画；高对比度、深色、浅色、中文/英文长文本和 `prefers-reduced-motion` 都要通过测试。
- 控件焦点不能跳出媒体 UI；关闭/收起后按规则恢复到触发控件或媒体。
- 页面 UI 不应修改页面滚动锁、body 样式、媒体尺寸或原生控件状态。

## 9. 完成判定

本需求只有在以下条件全部满足后才可标记 Verified：

- 页面默认不再显示视口级大面板；UI 与每个媒体实例正确跟随并可 teardown。
- 命令、快捷键和 UI 都产生同一格式的媒体级即时反馈；连续操作合并且最终值正确。
- 设置一次倍速后，新媒体、重播、SPA 换集和网站反向修改场景有自动化证据。
- hostile fixture 中网站以 setter、短间隔轮询和延迟重置反复写入倍速/音量时，保护开启后的实际值保持用户意图；关闭保护后网站写入可生效。
- seek 保护只在有界租约内阻止冲突跳转，自然播放时间持续前进；默认配置不改变网站正常换集、广告跳转和直播追帧。
- 腾讯等自定义媒体元素场景必须验证真实播放实例或自定义元素的实际值与时间增量，不能只验证扩展状态、storage 或隐藏辅助实例。
- 全局/站点/页面临时/当前媒体实际值四层作用域有 Schema、迁移、应用策略和冲突测试。
- Popup/Options 可解释当前策略和作用域；新用户无需预先掌握快捷键即可完成核心操作。
- 多媒体、音频、Shadow DOM、SPA、iframe、hostile/CSP 和 reduced-motion 场景无 P0/P1 未接受缺陷。
- 真实浏览器 headed smoke 至少验证控件定位、遮挡、焦点、触控/鼠标和反馈时序；fixture 不能单独作为体验完成证据。
