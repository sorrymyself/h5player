# 迁移策略与 Legacy 边界

> 文档 ID：ARCH-003  
> 状态：Approved as Planning Baseline  
> 负责人：Architect  
> 最后更新：2026-08-10  
> 关联：GOV-001、REQ-001、ADR-0001

## 1. 迁移策略

采用“平行绿地重构 + 行为对照 + 分阶段切换”的 Strangler 方案：

1. 固定 Legacy 基线，不在其上做结构性改造。
2. 新扩展先实现独立 contracts、runtime 和最小通用能力。
3. 按用户可感知的纵向切片逐步增加能力，而不是按旧文件逐一搬运。
4. 每个切片同时完成测试、诊断、权限和回滚设计。
5. 新旧实现可在测试页面或开发 profile 中并行对照，但正式用户环境只启用一个实现。
6. 扩展 Beta 后再决定哪些模型/工具值得抽取为共享包；抽取必须保持两个产品的发布独立性。

## 2. Legacy 稳定边界

### 2.1 默认不可修改

- `src/h5player.js`：历史早期单文件实现，仅作为行为资料。
- `src/h5player/`：油猴运行时、配置、GM 包装、UI、站点 TCC 和远程助手。
- `src/libs/`：油猴共用工具与兼容层。
- `config/rollup.config.js`、`config/rollup.tree.config.js`：现有油猴构建配置。
- `dist/h5player.user.js`：现有发布产物，不在重构 PR 中重建或格式化。

### 2.2 可以只读引用的内容

- 功能语义、默认快捷键、站点选择器和已知兼容问题。
- 现有配置导出样本（脱敏后）。
- 旧脚本在固定 fixture 中的可观测输出。

### 2.3 必须重新定义的内容

- GM API：不在新扩展中暴露兼容全局函数。
- 存储：不复制 `localStorageProxy`/`monkeyStorageProxy` 的隐式优先级。
- 消息：不复制 `postMessage` 字符串 type 和无校验 payload。
- 站点 TCC：迁移为声明式、可测试的 SiteAdapter。
- UI：迁移为独立应用组件，不复用 Legacy 编译产物。

## 3. 迁移分层

| 层           | 迁移方式             | 完成判据                          |
| ------------ | -------------------- | --------------------------------- |
| 领域模型     | 重新建模             | 类型、Schema、不变量和单测齐全    |
| 通用播放控制 | 行为对照后重写       | P0 命令 E2E 与差分结果通过        |
| 配置/快捷键  | 新 Schema + 显式导入 | 迁移、并发、恢复测试通过          |
| UI           | 重新组件化           | Story/组件测试和真实扩展 E2E 通过 |
| 站点适配     | 逐站点重写           | 每个适配器有 fixture 和 Tier 等级 |
| 实验能力     | 后置隔离             | 安全/性能/合规审查通过            |
| 远程助手     | 默认不迁移           | 价值、隐私和权限 ADR 批准后再做   |

## 4. 行为差分规则

差分只比较公开行为：

- 命令输入与可见结果；
- 媒体属性变化；
- UI 状态和可访问名称；
- 配置读写结果；
- 错误分类和降级结果；
- 初始化/销毁次数与性能指标。

不比较：内部对象结构、函数名称、全局变量、私有字段、旧脚本的未定义副作用和安全绕过行为。

每项允许差异必须登记在 `01-requirements/feature-parity-matrix.md` 的“差异说明”列，并由 Product Owner 与 Architect 接受。

## 5. 数据迁移

### 5.1 首发策略

新扩展首发不读取 Tampermonkey 私有数据库，也不在页面中自动猜测旧值。提供：

- Legacy 用户在油猴 UI 中导出标准 JSON；
- Web Extension options 中导入并预览变更；
- Schema 校验、字段映射、冲突策略和迁移报告；
- 原数据备份、失败恢复和撤销。

### 5.2 映射原则

- 可迁移：全局开关、站点黑名单、快捷键、媒体默认值、UI 开关。
- 需人工确认：旧版混合 local/global 配置、未知字段、站点自定义函数。
- 禁止自动迁移：任意 JavaScript 函数、远程助手缓存、原始媒体 URL、调试对象。

## 6. 切换与回退

- 开发 profile：可通过 feature flag 在新旧注入器间切换。
- Beta：新 runtime 默认启用，保留一键禁用扩展和回退到上一扩展版本的路径。
- Stable：只发布新 runtime；旧桥接入口保留至少一个版本周期，之后以 ADR 决定删除。
- 若发现 P0 回归，停止扩大灰度，发布上一稳定包；不修改油猴脚本作为紧急补偿方案。

## 7. 共享代码的准入条件

只有同时满足以下条件，才可考虑将代码抽到 `packages/shared`：

- 至少两个产品确实需要同一语义，而不是仅仅相似实现；
- API 已有稳定类型与契约测试；
- 包可以独立版本、构建和发布；
- 不携带浏览器/油猴运行时假设；
- 共享不会要求 Legacy 立即升级；
- 有明确的回滚和版本兼容策略。

## 8. 迁移完成定义

Web Extension 迁移完成不是“所有旧文件消失”，而是：

- 新扩展不依赖 Legacy 运行时产物；
- P0/P1 范围有验收证据；
- 明确记录未迁移功能和理由；
- Legacy 与 Web 的发布、测试、版本和故障互不阻塞；
- 后续是否重构油猴脚本可以基于真实数据和成本评估决策。
